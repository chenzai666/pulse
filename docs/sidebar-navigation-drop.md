# 侧边栏与标签栏导航修复

## 交互规则

- 侧边栏桌面、下载、固定目录、回收站和磁盘点击默认创建新标签，当前标签保留。
- 侧边栏右键提供“打开”“在新标签页打开”“在新窗口打开”；已有取消固定、徽标、清空回收站和隐藏 OneDrive 动作保留。
- 文件夹拖到顶部标签、标签关闭按钮、加号、标签组或顶部空白区，打开新的目录标签。
- 文件拖入上述区域时，只在新标签打开父目录并选中，不启动该文件。多个同目录文件合并为一个标签并多选。
- 内容区域继续使用原来的复制、移动、目录悬停与程序接收文件逻辑；标签排序拖动由原标签拖动模块处理。

## 后台解析与生命周期

`sidebar_navigation.cpp` 使用 `WorkerPool::EnqueueSerialIo` 处理拖入路径，再通过现有 `RunBoundedEnumeration` 读取文件属性。单个属性调用的等待预算为 1.5 秒，整批预算为 5 秒；失效项目跳过并提示，已完成的有效项目继续打开。

拖动悬停只读取命中区域和路径文本，不新增文件系统或 Shell 调用。路径拒绝相对地址、设备命名空间、ADS 和虚拟 URI。快捷方式文件作为普通文件选中，不解析或执行目标。

状态按窗口 HWND 独立挂载，结果消息只传生命周期令牌；后台代码不持有 `AppState`。销毁或隐藏窗口会取消未完成解析，旧窗口的迟到结果不能作用到复用 HWND 的新窗口。

导航结果返回时，重命名编辑、模态窗口及会触发 Shell 启动的网络快捷方式目标均拒绝交接，保留用户正在编辑的状态。

## 接线

宿主 `WndProc` 在取得 `AppState` 后调用 `HandleDroppedNavigationMessage`；返回 `true` 时消费消息。`WM_DESTROY` 在清理窗格和服务前调用 `CancelDroppedNavigation`。专用完成消息为 `WM_APP + 89`。

侧边栏延迟到鼠标释放的导航也应调用 `OpenSidebarPath`；不改动拖动、捕获、排序和释放的状态机。

## 定向验证

独立目标 `pulse_drop_navigation_test` 覆盖拖放效果、文件父目录/选中计划、UNC 文本路径、危险路径拒绝、失效源、多项目分组和取消。实际验证命令：

```powershell
cmake --build build-custom --target pulse pulse_drop_navigation_test
.\build-custom\pulse_drop_navigation_test.exe
```

界面验收需在独立测试窗口确认：

1. 分别点击桌面、下载、回收站、磁盘及固定目录，原标签内容不被覆盖。
2. 每类侧边栏右键的新标签/新窗口入口指向被点击路径，取消固定、徽标、清空等动作仍可用。
3. 分别向现有标签、关闭按钮、加号及顶部空白区拖入目录和文件；文件应选中且可见。
4. 混合文件/目录、多文件同目录、无效路径和慢 UNC 能得到明确结果；源文件未移动、删除或执行。
5. 内容区域复制/移动与标签排序仍遵循原行为；路径解析期间关闭窗口或关闭到托盘，旧结果不会重新打开标签。

编译与模型测试无法证明真实 OLE 拖入、最终选中行和菜单显示正确，交付时应分别说明这些环节是否实际验收。
