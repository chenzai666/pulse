# Pulse 定制版

当前版本号固定为 **v1.0.53**。项目主页、问题反馈和安装包均使用本仓库：

- 项目主页：https://github.com/chenzai666/pulse
- 问题反馈：https://github.com/chenzai666/pulse/issues
- 版本下载：https://github.com/chenzai666/pulse/releases

定制版未配置独立签名更新渠道前不自动更新到原版，第三方组件的来源和许可证保留。

基于 jimmgreen/pulse 的最新多窗口源码，保留 Win32、Direct2D 和 DirectComposition 主界面。

## 本次功能

- 标签保持排序、拖出独立窗口、跨窗口合并和窗格还原功能；离开标签栏只显示拖放预览，在内容区松手形成分栏，在窗口外松手才形成独立窗口。Esc 可取消。
- 侧边栏快速访问和磁盘入口点击默认在新标签打开；右键支持新标签和新窗口。文件夹或文件可拖到顶部标签栏：文件夹打开新标签，文件打开父目录并选中，原文件不会被移动或执行。
- 空格使用 Pulse 原生预览界面；随包内置的图像、RAW、音视频及压缩包增强组件保持启用。图片内容预览最长边提升为 4096 像素，列表缩略图及动画保留独立资源预算。QuickLook 宿主和完整插件仍随包保留，空格默认路径不启动它。
- FFmpeg、现代图像、RAW 相机照片和 7-Zip 预览增强包随完整包预置，设置页显示“已内置”，用户无需再次下载安装。启用开关和自定义 FFmpeg 保留。
- 新建标签页默认打开主页；“＋”和 Ctrl+T 使用相同规则。
- 恢复 Pulse 内置全局搜索、地址栏搜索、搜索子目录与 Ctrl+Shift+F 高级搜索。“搜索与索引”设置页支持全局快捷键、拼音及索引管理；Ctrl+F 继续筛选当前目录。全局搜索不依赖 Listary，不加载旧版 Listary 搜索桥。
- 定制版使用普通用户后台索引进程，扫描各本地磁盘中当前用户可读的目录，不使用原版共享系统服务。索引数据库、索引配置和索引进程日志统一放在安装目录的 `index` 文件夹，例如 `E:\PulseCustom\index`；升级保留索引，首次搜索需要等待建库，受保护或无法读取的目录不会绕过权限。安装目录不可写时明确失败，不自动改存 C 盘。
- “重复文件”设置页及自动重复扫描继续关闭。
- 文件右键“转换格式…”按所选文件提供共同可用的目标格式。Filee 无界面宿主、Pandoc 和常见转换引擎随包预置，首次使用无需另行下载增强组件。
- 工具栏删除会显示“永久删除，不放入回收站”复选框，普通删除默认不勾选；Shift+Delete 保留明确的永久删除确认。复选框每次重置，取消和关闭确认窗口不会提交删除任务。
- 右上角状态中心显示文件操作和格式转换的进度及本次运行的结果记录，支持取消仍在运行的任务；历史记录保留最多 64 条。
- 工具栏增加属性按钮，选中项目时显示项目属性；未选择项目时显示当前真实目录属性。窄窗口可以通过更多菜单访问。
- 默认属性窗口使用 Pulse 的主题和卡片样式，后台读取大小、占用空间、时间与只读／隐藏状态，支持多选汇总。目录链接不递归跟随，无法读取的内容明确标记为不完整；关闭窗口会取消读取。“系统高级属性”保留 Windows 的共享、安全、属性修改与扩展页功能。

## 运行与配置

完整解压后运行 pulse.exe；保留同目录的辅助程序、quicklook、packs、conversion 和 licenses 文件夹。定制版使用 %LOCALAPPDATA%\PulseCustom 保存配置，与原版 Pulse 的窗口和配置隔离。

程序安装目录需要允许当前用户创建和写入 `index` 子目录。索引位置跟随程序安装位置，不使用旧版 `%LOCALAPPDATA%\Pulse` 或 `C:\ProgramData\Pulse\Index`；卸载后由用户决定是否保留索引数据。

已部署的旧 Listary 插件可先备份，再移出 `Listary\FileAppPlugins\PulseCustom`，正常重启 Listary 后卸载其内存中的旧插件。只移除 Pulse 插件，不卸载 Listary 软件或修改其搜索设置。

### 文件弹窗

设置中的“文件选择窗口”可启用 Pulse 的打开、保存和选择文件夹界面；关闭后恢复 Windows 原版弹窗。不能可靠识别或权限不同的窗口保留原版流程。

Pulse 自身的文件管理、文件夹接管、全局搜索、索引、预览、主页、状态中心及标签拖动功能继续保留。Listary 可照常用于系统原版弹窗。

Pulse 弹窗宿主会初始化完整文字资源，取消按钮和侧边栏保留备用文字；切换到 Pulse 主窗口选择目录后再返回弹窗，可跟随当前目录，地址正在编辑时保留用户输入。该目录跟随无需安装 Listary。Windows 原版弹窗模式保留独立目录联动；两种模式不会同时修改同一个弹窗。

目录源会在主窗口激活和失活时立即更新，无需等待下一帧绘制。原版弹窗联动支持首次从 Pulse 切入打开／保存窗口，并短暂等待系统地址控件初始化；已有弹窗仍校验同一窗口身份。快速切回 Pulse 弹窗时，后台会重新读取来源目录后再交付，避免使用切换标签前的旧路径。

Listary 的原版弹窗底部搜索框由 Listary 自身挂接；Pulse 自定义弹窗通过可选的 `PulseCustom.FileDialog` 插件识别协议支持其搜索栏。搜索栏由用户安装的 Listary 提供，不随 Pulse 捆绑其闭源程序。未安装 Listary 或对应插件时，Pulse 的当前目录搜索和目录联动继续独立工作；Listary 搜索结果只导航或填写名称，由用户点击打开／保存确认。

启用“文件选择窗口”接管后，Pulse 选择窗口会保留到原应用确认接收或取消成功，随后才关闭。确定尚未发送确认的错误可在 Pulse 内修改后重试；确认已经发出但结果不明确时禁止重复发送，并提供取消操作。常规提交失败不会改为原版窗口要求用户再次打开／保存；在设置中关闭接管时恢复原版窗口。宿主异常且取消失败时，Pulse 主窗口显示恢复提示，用户可以通过关闭接管恢复原版。

测试版不接收上游自动更新，避免更新覆盖定制功能。完整包中包含对应源代码和第三方许可证。

## 常见格式转换

选择文件后右键点击“转换格式…”，选择输出格式和保存位置。转换在后台进程中运行，进度提示支持取消，完成后点击“查看输出”会打开新标签。切换标签不会改变本次转换的源文件。

| 文件类型 | 首版范围 |
| --- | --- |
| 图片 | JPG、PNG、WebP、BMP、GIF 互转；HEIC、AVIF 转常见图片；图片转 PDF |
| 文档 | DOCX、XLSX、PPTX 等常见 Office 文件转 PDF；PDF 转图片 |
| Markdown | 内置 Pandoc 支持 Markdown 转 HTML、DOCX；PDF 使用随包附带的文档渲染链路，无需另装 TeX |
| 视频 | MP4、MKV、MOV 互转；提取音频及生成 GIF |
| 音频 | MP3、WAV、FLAC、AAC、M4A |
| 压缩包 | ZIP、7z、TAR、TGZ 转换或解压；RAR 只读取 |

一次最多处理 128 个文件，单个输入上限 2 GiB。输出采用新文件名，遇到重名自动追加序号，不覆盖原文件。旧版 DOC、PPT 未预置 LibreOffice 转换引擎；复杂图表、公式、修订、字体和版式可能无法完整保留。能力菜单表示引擎路由可用，损坏、加密或内容特殊的文件仍可能转换失败。

## 构建

使用 GitHub Actions 的“构建 Pulse 定制版”工作流，或者 Windows x64 Visual Studio 2022 C++ 环境执行：

```powershell
pwsh -File scripts/build_custom_ci.ps1
```

云构建按改动范围执行相关回归，校验组件后再打包。移除文件弹窗接管时验证旧设置迁移、系统集成设置布局、Pulse 内部选择器及正式程序中无接管入口；本机验证打开、保存和选择文件夹均保留 Windows 原版。

恢复搜索可选择 `validation_scope=search`：复用已逐文件验证的完整组件，只重编译主程序与索引进程，验证真实索引查询、安装目录存储隔离、搜索结果路由及设置页，再生成正式载荷。安装器使用同一提交的搜索验证记录，应用版本仍为 v1.0.53，独立发布标签为 `custom-v1.0.53-search`，不覆盖此前已发布的标签或资产。

属性界面修复可在工作流手动运行时选择 `validation_scope=properties`：只编译主程序、属性元数据测试和属性窗口画廊，复用固定提交 `9817d635b` 的完整组件包，验证 GitHub 摘要和每个文件后重新打包。此路径会拒绝既有组件源码变更，固定构件过期时应选择默认 `full` 完整构建。属性画廊检查浅色、深色、高对比度、100%／150%／200% 缩放及加载、多选、错误、窄窗口状态。

标签、回收站、原生图片预览和全局搜索修复可选择 `validation_scope=native-fixes`：复用逐文件校验的 `4c456fe91` 完整运行时，重编译原生组件并执行对应筛选用例。发布主程序在移除自检入口后重新构建；回收站接管分别验证 `open` 和 `explore`，仅更新回收站关联，并保留快照与范围明确的恢复命令。
