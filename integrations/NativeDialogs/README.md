# Windows 标准文件选择窗口接管

Pulse 的“系统接管 → 文件选择窗口”可用于支持的软件中的 Windows 标准打开文件、保存文件和选择文件夹窗口。此选项默认关闭，由“系统接管”总开关控制，可独立取消。

## 支持范围

- 支持同一用户、同一桌面且权限相同的软件中的可识别标准窗口。
- 软件自绘窗口、网页内选择界面以及无法确认状态的窗口自动保留系统原版。
- 管理员软件、其他用户会话、受保护桌面或权限受限的软件自动保留原生窗口。
- 不支持的软件自动保留系统原版。是否支持以实际窗口能否安全识别为准。

## 使用和回退

1. 打开“设置 → 系统接管”，开启总开关，再勾选“文件选择窗口”。
2. 在支持的软件中选择打开文件、保存文件或选择文件夹。Pulse 显示自己的选择窗口，原生窗口和宿主程序始终保留。
3. 选择完成后，宿主程序继续负责路径检查、覆盖确认以及实际打开或保存。Pulse 选择窗口本身不会打开、创建或覆盖所选文件。
4. 取消“文件选择窗口”、关闭总接管，或点击“恢复原版”，停止后续接管，关闭当前 Pulse 选择窗口，并恢复原生窗口的可用状态。宿主程序已有输入和对话框状态保留。
5. Pulse 主进程异常退出时，独立选择窗口会主动退出并恢复曾被它临时禁用的原生窗口。原先已禁用的窗口不会被强制启用。

## 安全与边界

接管不隐藏、不销毁原生窗口，也不改变第三方窗口样式。Pulse 的选择窗口显示在原生窗口上方。识别失败、权限不足、选择窗口启动失败或接管被取消时，保留原生流程。

返回结果最多包含 256 条路径，每条最多 32768 个字符，总数据最多 1 MiB。超过限制或数据不完整时拒绝接管结果，保留宿主原生窗口，避免截断文件名或静默漏选。

此功能依赖 Pulse 运行；启用该选项和总接管后，关闭主窗口会保留后台运行。关闭总接管后，这项功能不再要求 Pulse 留在后台。

## 定向验证

开发构建提供以下定向入口：

- `PULSE_SELFTEST_CASE=native-dialog-wire`：请求与返回数据完整性、路径和过滤器往返、截断/错误数据拒绝以及数量与大小限制，日志为 `bench_data/native-dialogs-wire.log`。
- `PULSE_SELFTEST_CASE=native-dialog-takeover`：在独立桌面中运行真实原生窗口和生产接管器，验证打开、保存、现代及旧式目录选择、取消、停止后恢复、再次接管与父进程死亡恢复，日志为 `bench_data/native-dialogs-takeover.log`。
- `pulse_file_picker_model_test.exe --save` 和 `pulse.exe --picker-dialog-test --save`：验证保存候选路径、扩展名、导航和界面交互；保存用例不得创建或覆盖候选文件。

端到端测试创建专用桌面，不切换用户桌面；只运行并清理自己创建的测试进程与临时文件。

该测试不代替真实软件中的打开、保存、选择文件夹和取消回退验证。发布前应在普通权限的受支持软件中分别验证这些流程，以及关闭子选项、关闭总开关、“恢复原版”和 Pulse 主进程退出后的原生窗口恢复。
